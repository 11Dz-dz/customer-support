# 同款颜色和尺寸查询

更新：2026-11-03。代码入口为 `backend/catalog/product_variants.py`，任务类型为 `product_variants`。

## 遇到的问题

推荐了商品989（Mountain-500 Black, 40，历史目录标价539.9900）后，用户问“那别的颜色呢”，系统却回答未找到足够符合描述的推荐。

原因不是数据库没有其他颜色。此前用户要求更便宜，任务留下价格上限564.9899；同型号银色40码商品984的价格为564.9900，被旧价格过滤掉了。另外，原路径仍按“性价比高”做推荐检索，没有用当前商品的型号锁定其他颜色。最终描述精选返回空，通用回复也没有说明真正的原因。

## 现在如何处理

1. 路由识别为“同款规格查询”，不是重新推荐；模型负责识别意图，程序核实商品引用和条件。
2. 从已展示商品、明确商品编号或任务依赖确认参考商品；多款商品无法确定指代时先询问用户，不猜编号。旧失败任务清空展示列表时，只从有成功工具证据支持的销售回复商品标题恢复引用。
3. `query_product_variants` 根据数据库 `product_model_id` 查询同型号。问颜色默认保留原尺寸；问尺寸默认保留原颜色。不是拆商品名称猜型号，也不经过向量召回和推荐精选。
4. 程序展示数据库中的商品、颜色、尺寸、价格及差额，不让模型编造这些数值。新建查询任务，保留原推荐任务与条件。

## 展示其他颜色，不等于符合原预算

普通“那别的颜色呢”：展示同款资料，同时标注原价格条件。上述例子会显示商品984、Silver、40、564.9900，比原商品贵25.0000，并说明不符合原价格上限564.9899。不会把它说成预算内推荐。

“预算不变，只看符合价格条件的其他颜色”：严格筛选；没有符合项时说明同款有银色，但不符合价格条件，并提供被排除款式的最低历史标价。不会将其列为符合条件的款式。

“预算提高到600，其他颜色呢”：新查询使用用户明确给出的600上限，银色款可符合条件。价格比较和金额差额由程序使用Decimal处理。

显示银色款后，再问“按刚才的银色款买两件”，报价引用实际展示的商品984，标价小计1129.98，而不是继续引用黑色989。多个款式未选定时仍须澄清。

## 代码分工

| 文件 | 职责 |
|---|---|
| `backend/catalog/product_variants.py` | 核实引用、绑定颜色/尺寸条件、区分展示和严格筛选、渲染结果 |
| `backend/orders/adventureworks_service.py` | 参数化SQL按同型号及另一规格查询，计算价格资格和差额 |
| `backend/agent/business_tools.py` | 暴露只读工具 `query_product_variants` |
| `backend/tasks/task_state.py`、`backend/tasks/task_scheduler.py` | 保存新任务、参考商品和等待补充状态，不覆盖原推荐 |
| `backend/tasks/task_execution.py`、`backend/agent/tool_execution.py` | 按确认后的参数直接查询，拒绝工具擅自放宽预算或更换商品 |
| `backend/agent/answer_contract.py`、`backend/agent/langgraph_supervisor_1.py` | 收集展示商品，走事实展示并支持后续报价 |
| `prompts/router.md`、专家配置 | 告诉规划器何时使用新任务，将工具加入销售白名单 |

目前业务工具共13个，销售白名单6个；本次没有新增Skill或前端依赖。

同款查询与预算筛选的回归见 `tests/test_product_variants.py`。
