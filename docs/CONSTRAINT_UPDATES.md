# 用户条件保留、字段更新与百炼接入

更新日期：2026-11-03。商品大类、具体商品类型、颜色、尺寸和价格的主路径现使用query_update与catalog_filter；报价增加逐商品quote_items，统一quantity仍兼容。本页保留仍运行的旧标量兼容路径和此前验证记录。当前主路径详见[统一商品查询说明](CATALOG_QUERY_CONTRACT.md)，任务交接与报价变化见[稳定性改进](RELIABILITY_IMPROVEMENTS_20261103.md)。

## 原来会出什么问题

用户先说“推荐一款自行车”，再补“预算500以内”。如果模型把任务改写为“推荐五款配件”，类型和枚举校验仍可能通过：配件是合法类别，五也是合法数量。工具和任务的类别保持一致，只能证明执行没有偏离任务，不能证明任务符合用户原意。

另一个问题是默认值覆盖。原任务明确包含同型号不同规格，模型新一轮只填写预算；旧合并过程会把未填写选项的默认false也带入，重置用户选择。此前数量保护只解决一项字段，不能推广为所有条件已有保护。

## 现在怎么做

1. 模型负责理解请求、识别任务归属和语义需求。当前商品类别、颜色、尺寸和价格通过query_update提出；展示数量、报价数量及旧适配器继续使用field_updates，不把整段改写直接当作条件。
2. 每项变更包含字段、set或clear、新值、当前原始输入的数组索引和连续原文。首次请求的明确条件也需要依据；默认展示5款等系统默认值不编造用户来源。
3. 程序核对真实原文来源、数值及字段范围。新协议由模型表达包含/排除和AND/OR，程序校验类型、价格依据、补丁及冲突，不用类别名出现与否推翻语义。旧标量路径的词汇/单位校验继续服务旧适配器；它不是所有否定表达的语义证明。
4. 同一任务只合并已批准变更。没提到的字段继承；明确取消才清除；明确修改为false才设false。保留字段的显式填写状态，避免Pydantic默认值变成主动修改。
5. 为兼容已有检查点和适配器，单一商品任务还允许程序直接从原始输入规范化可确定字段；不从模型改写的query补造条件。多个对象不套用全句字段，要求任务各自引用所属的原文。
6. 新条件冲突或无法可靠核对时，保留原任务并询问用户，不先执行一部分新查询。规划器也可显式返回clarification，但仍需保留非空任务候选；已知任务缺必填信息时保存为awaiting_input，不能只返回一句问题而丢掉任务。任务引用歧义和字段冲突分别记录。
7. 程序安排的查询使用已批准任务的价格、类别、颜色和尺寸；模型另行提交的工具请求若遗漏、扩大或重新加回已清除条件，则在执行前拒绝，不改写模型原始调用记录。关键词、向量检索及历史候选复用均检查这些条件；颜色和尺寸在召回前进入SQL，不只在拿到前几个之后筛选。
8. 成功空检索的全目录核对也带上颜色和尺寸，回答说明对应条件，避免“尺寸99没有商品”被误说成所有自行车都没有。

例如，“预算500以内”只更新max_price；“换成头盔”允许更新类别；“颜色不限”清除颜色；“每款买两件”不把展示一款改为展示两款。

## 来源记录与日志

ConversationTask.parameter_sources保存每个已核实字段的原文、当前输入索引和任务revision，parameter_changes保存本次批准变化及忽略的无依据提议。原始用户消息仍由原会话记录保存，不用任务改写替代。

本地task_parameters_updated事件只记录任务ID、revision、字段、动作和来源索引，不把用户原文或参数正文新增到事件日志。需要原文时查看受权限保护的会话状态或按既有脱敏/隐藏配置的LangSmith链路。普通用户页面继续不显示请求编号。

## 哪些没有变成程序保证

此轮统一更新的范围是商品推荐、目录查询和报价条件。订单/商品ID的已验证引用、账户身份和权限继续由原来的专门逻辑处理，不把它们当作模型可随便修改的字段。任务归属、自由文本需求和用途适用性仍需要模型理解。

这里的原文片段验证不是通用语义证明。业务词表和表达范围之外的硬条件可能触发澄清，不能声称覆盖所有中文表达。引用真实原文也可能理解错误，因此仍需固定反例和真实模型评测；多模型投票不能代替权限与SQL校验。长途骑行推荐相关性没有在本轮重新定义或宣称解决。

## 百炼的DeepSeek配置

百炼Key与DeepSeek官方Key不可混用。保留DEEPSEEK_API_KEY这一项目配置名，通过另外三项选择提供商：

```dotenv
DEEPSEEK_PROVIDER=bailian
DEEPSEEK_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
DEEPSEEK_MODEL=deepseek-v4.1-flash-1017
```

此处为已验证的北京共享兼容地址；其他地域/业务空间须使用对应地址和Key，不自动将Key轮流发给其他服务商。模型创建、评审和健康检查统一读取配置。端点只允许所选提供商的HTTPS域名，不跟随健康检查重定向。业务规划和工具选择使用非思考模式，以保持当前有界响应时间；适配器仍保留真实reasoning字段协议支持。

官方资料：[百炼DeepSeek调用参考](https://help.aliyun.com/zh/model-studio/deepseek-api)、[V4.1模型](https://help.aliyun.cn/zh/model-studio/deepseek-v4-1-flash)。本轮先验证Key可调用固定1017版本，未仅凭模型回答中的自我介绍判定版本。

## 回归中继续发现的问题

- **换类别附带取消预算：**模型提出了用户未要求的清除。最初把整项变更全部拦住，造成正常换头盔也不能完成；改为保留没有依据的无关字段，执行已核实的有效变更。真正涉及该字段但值不一致时仍要求确认。
- **提高预算被误作重试：**空检索属于已完成的业务结果，不能冒充失败工具。程序发现明确的新条件与旧值不同，就按修改任务处理，沿用新的过滤条件，而不是重放旧参数。
- **购买数量与展示数量混用：**推荐和报价可以同时存在。“推荐一款”和“每款买两件”分别属于展示数量和购买数量；统一更新按字段适用任务划分，不能因为同一句涉及两项任务就丢掉预算或购买数量。
- **目录词汇需要对齐真实分类：**AdventureWorks轮胎和内胎属于子类别37，即accessories；日常语言把它叫零件，不等于数据库的components类。SQL核对后调整业务词表，并处理“旅行车把/公路车内胎”等对象修饰，避免把车把或内胎当整车。
- **正常表达误拦：**统一规范化“44码”、标价最高/最低、多少条、排除0标价等字段表达；数字尺寸按目录字符串保存。没有为整句测试问题增加业务路由分支。
- **单独取消上限不应删除下限：**“不设上限”只清除max_price，仍保留已有min_price；“不设下限”反之。新增反例测试。
- **澄清丢掉任务：**模型对无效订单号直接提问且tasks为空，后续没有等待订单号的任务。现在结构校验要求非空任务候选；已知任务缺必填字段时保存等待状态，真正归属歧义仍停止执行并保留原任务。
- **来源记录挤占上下文：**完整原文保留在状态中，提供给规划器的任务摘要只携带来源索引、操作和revision，避免重复加入长原文；测试验证压缩不修改原记录。


## 执行链路也要保留真实提议

最终审查发现，静默把工具请求中的错误参数改成正确参数，可能把模型原本的提议与程序实际执行混在一起。这会影响LangSmith排查和失败操作台账。因此最终改为先检查、不一致就返回TASK_TOOL_NOT_ALLOWED，不修改原始tool_call；程序安排的种子查询本来就使用已批准条件。新增测试同时检查：错误请求不执行、原始字典不变、错误码明确；正确及已清除条件的请求可以原样执行。

已清除预算、颜色、尺寸不能被后续模型工具调用重新加回。当前任务中的null与未限定也是执行约束的一部分，不只是校验非空条件。改变条件后的商品引用同时失效，避免沿用旧筛选下选中的商品。

## 仍需保留的限制

多次真实运行中出现过一次“先1000、后500”被模型不必要地追问的情况，以及模型调用等待超时；即使最终批次通过，也不能宣称这些情况永远不会再发生。程序不会因此执行未核实的新条件，但可能需要用户补充或重试。自由文本需求、任务绑定和是否需要澄清仍有模型参与。


重复旧值不视为新修改：模型换类别时若顺带复述原预算，其值与已批准值相同，则保留原值和原依据，不要求伪造新的原文引用，也不覆盖来源。当前用户有明确的新值时仍按真实输入合并。这解决了“预算未变，却因引用上一轮原文而阻止换头盔”的实测失败；原记录保留。

一次传输连接中断时，尚未更新的目录曾开始自动测试；发现后停止并保留该中断日志。重新传输、核对安装包哈希后，使用单独的v11-final日志启动最终完整验证，不把中断运行算入最终成绩。



## 网页追加换类别暴露的校验纠正缺口

能确认的是失败发生在规划字段校验，字段为limit。当前LangSmith密钥是tracing key，只允许上传，SDK读取历史链路返回runs:read的403；清理临时会话后，不能从本地状态还原那次模型完整候选。分别对无旧任务、已有待执行任务、已有完成任务进行了三次诊断，均未复现该异常，因此不把“模型一定拆成两项”等推测写成事实。

**改进：**格式修复与字段提议修复共用一次纠正额度。只有模型提议缺少依据、且该字段可以从原始输入核对或确实由模型无中生有时，才把错误字段、原因和未提交候选反馈给DS；要求根据全部原始输入重建计划，再执行原来的全部校验。首次无保存任务时，应合并同一目标的补充条件，不能虚构旧任务ID。纠正前不提交任务、不执行业务工具；第二次仍失败则保留原任务并澄清，不无限循环。

真实的价格上下限冲突、多个商品任务的归属歧义不交给模型猜测。如果用户确实提出当前规范化器不支持的明确条件，如紫色，也不允许借纠正机会丢掉该条件。模型超时、服务商错误不通过此机制自动重试。新增反例验证一次纠正成功、二次失败不提交、与格式修复合计最多两次调用、真实价格冲突不重试、不丢掉未支持的明确颜色条件。plan_constraint_retry事件记录错误字段，真实纠正模型调用照常进入LangSmith。

这增加的是有界纠正能力，不是让不合法计划绕过验证，也不保证每次模型都能理解正确。最终网页复测与回归仍单独记录。

## 新请求尚未交付时，明确替换不能保留旧目标

**v14的改法：**在任务创建前核对本处理段的原始输入。如果没有已保存任务，最初只有一个明确商品类别，后续明确说“换成/改为”另一个类别，而且没有“另外、同时、都要、再推荐”等独立需求词，则两份候选中只保留最后类别那一项，合并为一个目标。然后再次按全部原始输入验证字段，继承一款，使用最新100预算；不是直接信任模型候选参数。任务变更记录中加入collapsed_unpublished_replacement，便于追查。

该规则只处理可明确核对的、当前未提交的新商品推荐替换链。存在已保存任务、多个原始对象、任务依赖、取消/失败重试或不明确的对象时不自动合并，继续原有目标校验/澄清。已有任务的修改仍通过task_id与原字段更新处理。同属一个大类但语义对象不同、含复杂省略的表达仍由DS规划，不能声称程序已经覆盖所有替换。新增6项自动测试检查正常合并、独立目标不合并、已有任务不重绑定、多个对象不猜、依赖不删、后续明确数量覆盖。

## 2026-11-04 数量误识别与规划诊断

M09第二轮询问商品776标价，却要求确认展示数量。旧纠错规则匹配单字“个”，将“换个问题”误认为用户提出了数量要求，阻止一次自动纠错。

新增presentation_count_matches，返回原文中的span、value、unit。数字加量词、前N和topN能够形成数量意图，“换个”“这个”“一个问题”、编号和时间表达被排除。“几款”保留未知值，交由既有流程处理。这里的匹配用于纠错许可，字段赋值继续经过原有任务数量校验。数量或金额的实际条件仍须有对应原文依据。

新增后端planner_diagnostic事件，记录数量规范化前的解析候选、任务准备后的计划、转换原因、准备阶段参数来源、拒绝字段及所属任务、数量匹配、纠错许可与跳过原因，以及实际序列化上下文的字符数和哈希。校验仍按首个错误返回，日志明确标注first_error。候选来自结构化接口解析后的对象，服务商原始响应正文尚未保存在这类事件中。诊断事件写入logs/web-events.jsonl并关联已启用的LangSmith链路，网页流只接收原有公开事件。日志复用已有凭据脱敏，超过120000字符时保留截断标记与哈希。

任务转换条件已经核实。只有缺少商品编号、带关键词且无依赖的product_detail才转为product_search。有编号且同时带关键词的详情任务继续按编号查询。准备阶段日志中的model表示模型提交字段，default表示模型未提交的默认值，inherited表示准备任务时沿用的值，program用于程序管理字段。后续条件校验仍可能修改或拒绝这些准备值。

## 2026-11-04 商品经营咨询与目录覆盖检查

问题出在两层。EV_OV07询问电动汽车是否销售时，模型会在拒绝与目录总览之间摇摆；总览只列类别，仍没有回答具体品类。EV_OV08的儿童滑板车则容易落入推荐流程，返回候选证据不足。

新增catalog_query的coverage操作，requested_item引用原文完整对象，保留电动、儿童等修饰。程序使用product_taxonomy的受信任别名及现有类别映射确认类型，只在对应分类确有记录时返回CONFIRMED。自由文本与模型建议检索词只形成RELATED_ONLY文字相关候选。名称、型号、中英文描述中的英文检索采用字母数字边界，car不会命中carrier。模型无需提交mapped_categories，实际映射全部由程序确定。

NO_EVIDENCE只表明本次在已说明的字段和检索词下未找到证据；CHECK_FAILED表示数据库或参数导致检查未完成。四类结果使用受控回复。已分类和未分类记录一并检查，记录缺失描述数量。当前504条记录中209条未分类且没有描述，回复说明只能核对这些记录已有的名称、型号等字段。实时库存和在售状态继续标为无法确认。预算过严的已知品类查询继续使用原list/count空结果，不用覆盖状态代替。

范围规则迁入prompts/scope.md，router.md补齐覆盖问法和out_of_scope规则。拒绝任务新增可选scope_reason及source_index、source_text，TaskPlan重建时显式保留，并用私有诊断保存重建前候选。历史会话缺少新字段仍可读。覆盖对象必须在已核对的本轮原文片段中；单任务可以使用整句，多任务须提供片段。
