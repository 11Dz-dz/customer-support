# 按需真实健康检查

项目：`/root/rivermind-data/Agent/example/langgraph_olist_example/`。

## 遇到的问题及改进原因

### 固定示例被说成当前监控

原check_system_status始终返回数据库小于10ms、CPU 85%、API所有端点可访问，没有实际探测。改成带时间、耗时和范围的真实只读检测。错误码解释是静态知识查询，不需要伪装成实时监控，因此保留原映射。

### 容器指标容易被宿主机资源误导

当前实例是有限CPU和内存配额；直接使用宿主机核数或总内存会失真。优先读取cgroup v2计量，回退时明确写宿主机视图；指标缺失不能算全部正常。

### 一个接口成功，被扩大成所有服务正常

模型列表HTTP200只能说明该接口及本次鉴权通过，不能证明账户余额、对话生成或其他端点正常。限定探测目标与结果表述，分别处理401、403、429、超时和异常响应，失败时报告失败或未确认。

### 旧快照和模型草稿可能冒充本轮事实

每轮当前状态重新调用工具，只从当前用户消息后的检测结果生成正文；不直接展示模型草稿。测试核对检测时间更新、草稿隔离，以及流式和持久化正文一致。

### 模型不可用时，依赖聊天才能检测会失效

新增不经过LLM的独立命令，便于直接读取健康结果；API探测仍需现有Key。没有借此启动后台服务或执行自动修复。

下面说明具体实现、使用方式和实测。想先理解程序究竟检查了什么，请看 [通俗版总总结](IMPROVEMENTS_READABLE_20261021.md) 第7节。

## 检测范围

### PostgreSQL

使用现有`DATABASE_URL`连接，以只读事务执行`SELECT 1`。连接配置默认超时5秒，探针查询设2秒上限；在客服请求内还受到本轮剩余期限约束。记录实际连接及检测耗时，不访问订单、用户或退款业务表。通过仅代表本次连通和简单查询成功，不等于复杂业务性能或全部数据库功能正常。

### 服务器资源

CPU使用0.25秒计数器差值。优先读取cgroup v2配额和CPU用量，分母为当前容器CPU配额。内存读取同一容器的memory.current/memory.max，包含文件缓存，不能当作Python进程RSS。

无法读取有限容器配额时，回退到/proc并明确标注“宿主机视图”，不把它伪装成容器使用率。无法读取的指标列为缺失，不能报告全部正常。

系统目录和项目目录分别查询所在文件系统的占用与剩余空间；可能共用同一文件系统，也不代表云平台给容器设置的磁盘配额。CPU、内存或文件系统使用率达到90%时提示关注。短时高占用不直接断言持续故障。

### DeepSeek API

固定访问官方HTTPS目标`https://api.deepseek.com/models`，沿用现有Key。只执行GET，默认最多等待5秒；客服请求内按剩余预算缩短等待，不自动重试、不跟随重定向，不发送用户聊天内容。限制响应大小，响应正文和请求密钥不进入工具结果。

HTTP 200且响应结构正确时，记录配置模型是否在列表中。缺少模型时只提示需要关注，不直接断言别名不可用。分别处理401、403、402、429、网络/TLS错误、无效响应和未配置Key。

依据官方文档：[获取模型列表](https://api-docs.deepseek.com/zh-cn/api/list-models/)。这个检查不验证对话生成、账户余额或其他端点，不会展示“所有端点可访问”。

## 使用

重启正在运行的命令行助手后，可以问：

1. 检查一下服务器现在的CPU、内存和磁盘使用情况。
2. 检查PostgreSQL现在能否连接，告诉我实际检测耗时。
3. 检查DeepSeek接口当前是否可访问，并说明检测范围。
4. 再检查一次服务器，使用最新结果。
5. 500错误码一般是什么意思？不要检测系统。（只调用错误码查询。）

不经过LLM直接检测：

```bash
cd /root/rivermind-data/Agent/example/langgraph_olist_example
/opt/conda/envs/agent/bin/python health_monitor.py --component all
/opt/conda/envs/agent/bin/python health_monitor.py --component server
```

独立命令返回JSON；全部healthy时退出码0，其余为1。它无需先调用聊天模型，模型服务不可用时仍可运行。API检查仍需要Key；仅检查server/database不需要模型调用。

## 时效、输出和边界

每条结果包含UTC检测时间、实际耗时、状态和范围。本轮相同只读请求可能由现有工具去重复用一次快照；跨轮重新检测。不会用历史会话中的状态冒充本次检测。

技术支持正文改为节点完成后分段发送；真实健康指标由程序从工具结果展示，流式正文与会话持久化正文一致，不直接展示模型草稿。只有错误码解释时，error_explanation直接映射search_error_code，collect根据工具文本展示错误码及含义，不因此运行健康探测。

这是按需实时健康检查，没有后台定时采样、指标时序库、历史曲线或主动告警；不执行重启、修改配置、退款或其他修复动作。没有检查GPU、应用进程存活、业务请求成功率或端到端订单流程。
