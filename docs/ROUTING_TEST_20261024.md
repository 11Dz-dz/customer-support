## 问题一：N01、N20专家模型HTTP400，自动检查漏检

两题都是推荐一款商品并查订单，单号稍后补。search_products成功，但销售专家请求返回OpenAIInvalidRequestError/HTTP400，推荐任务状态partial，failure_code为EXECUTION_FAILED。程序用已取得候选保守回答，并说明异常；下一轮仍能查订单，未重做推荐。

原预期检查了检索、展示数量、保留待补订单以及下一轮查询，未要求推荐任务completed或每次专家模型调用成功，所以仍自动通过。原成绩不改，补充复核单列问题。

额外诊断再次返回HTTP400，服务明确提示：thinking模式必须回传reasoning_content。这是工具历史与模型协议的兼容问题，应重点核查seed_product_search构造的AI工具请求及ToolMessage如何进入专家输入。已确认接口报错原因，尚未实施修复；不是余额不足或简单网络超时。

## 问题二：N10未选择商品时，先澄清还是分别报价

先介绍商品915与946，再问“刚才的买两件是多少钱？我还没选哪一款”。预期先问选哪款，实际分别计算两件的报价：915为78.28，946为92.18。

原规则仍记失败，但实际没有擅自选择一款、合成订单或执行购买。这是是否允许主动给出分别报价的策略边界，不等同于金额错误或越权。后续应先确定交互策略；本轮未修改预期或业务。

## 其他样本观察

- 两笔等待任务收到裸订单号时先澄清，用户明确第一项后才查询。
- 预算修改和清除只改变指定字段，新订单任务未继承商品颜色、预算。
- 报价数量从待补到三件再五件，工具计算正确。
- 等待订单时插入404解释，随后能回到原订单任务。
- 取消单项保留另一项，取消查询不声称取消业务订单。
- 订单到商品详情与独立报价按任务分别执行，商品来自真实订单返回。
- 自己订单成功、他人订单拒绝，游客和聊天伪造身份不能获得订单权限。
- 退款咨询没有提交申请或擅自转人工。
- 一次受控支付查询超时后，只重试支付，不重查成功订单与发票。
- N16取消任务曾触发一次schema格式修正，随后成功，没有业务副作用。

以上仅代表本轮样本；AI辅助复核不是独立人工验收。
