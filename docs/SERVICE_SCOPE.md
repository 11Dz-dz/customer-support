# 客服服务范围与无关问题处理

本项目保留 River 客服身份，服务范围为商品咨询、订单账单、退款入口及进度、人工工单，以及本客服系统和运行环境的故障排查。没有改成智川云官方客服。

## 为什么修改

此前 general 任务允许专业领域的复杂咨询，但没有明确的无关请求出口，写算法等问题可能被归入技术支持并生成通用回答。本次增加统一范围说明和程序固定回复。

## 当前流程

1. `prompts/scope.md` 集中定义业务范围，路由和三个专家均读取。范围规则每次必需，因此属于基础说明，不做成按需 Skill。
2. 同一个路由模型在原有任务规划中识别相关与无关部分，没有再新增分类模型或额外分类调用。
3. 无关部分生成 `conversation` 任务，`conversation_intent=out_of_scope`。不生成算法、作文或其他正文；`general` 不能用作无关请求的兜底。
4. 程序跳过业务工具和专家推理，使用 `conversation_replies.py` 的固定范围提示。`scope_refused` 事件关联原有请求、会话及任务，不额外记录用户正文。
5. 混合请求照常执行相关业务，另附范围提示；不因为有无关问题就丢弃订单查询等合法需求。

例如“写一个冒泡排序”返回固定提示，不给代码。“查订单应付金额，再写一首诗”返回订单事实并拒绝诗歌部分。“帮我查订单，我下一条给编号”后插入算法问题，原订单等待任务保留，之后仍可补编号。

固定提示为：

> 我只支持商品咨询、订单账单、退款进度、本客服系统的技术支持和人工工单相关问题，不能处理无关请求。你可以问商品推荐、订单状态、退款审核进度，或本系统的连接和 API 报错。

## 维护位置与边界

| 文件 | 维护内容 |
|---|---|
| `prompts/scope.md` | 允许范围、真正需求判断、混合请求与指令覆盖的处理 |
| `langgraph_supervisor_1.py` | 路由输出约定、固定回复事件；沿用现有图和流式输出 |
| `specialist_config.py` | 各专家统一加载范围说明，约束误路由后的自由回答 |
| `conversation_replies.py` | 修改固定的用户提示文字 |
| `task_state.py` | 新增会话意图枚举；拒绝任务的参数、取消、重试、依赖和继承字段归零 |
| `tests/test_scope_boundary.py` | 拒绝无执行、旧任务保护、混合业务和后续订单号测试 |
| `evals/scope_runner.py` | 真实模型的无关、包装、指令覆盖、混合与多轮场景 |

问候、感谢、告别与能力介绍仍允许；订单号、预算、规格等短输入结合当前任务理解。相关业务缺少政策、权限或数据，继续按原逻辑说明未知或缺失，不改成“无关”。单独的拒绝任务不能取消、修改或重试原任务，也不能作为业务任务依赖。

技术范围是本客服系统及其运行环境的问题。给通用算法套上商品、订单或 GPU 的背景不会使其成为业务咨询。此修改没有新增技术故障 Skill、通用编程能力、外部知识库或业务工具。

范围分类仍依赖模型语义判断，不是关键词黑名单，也不能声称对所有改写或对抗输入零误判；固定回复和无工具执行由程序保证，前提是路由已识别为无关。测试用于检查具体边界，不代替未来持续回归。
