# 动态模拟用户评测

本评测借鉴τ-bench的目标驱动交互方式，运行本项目完整客服图，使用自己的工具、身份规则和AdventureWorks目录。不是官方任务集，不可与官方榜单比较。网页退款、同时追加消息和故障恢复继续由对应HTTP与故障注入测试验证。

## v3款式数量验收口径

数据集版本为dynamic-customer-v3，评分器版本为dynamic-display-v1，款式口径为actual-spec-v1。D01、D02、D04要求三款，D03、D18要求一款；其余题目原有验收条件不变。

“款”按实际商品信息区分：同一型号的颜色、尺寸、名称、重量或描述等商品属性不同，算不同款。商品完全相同时不能重复计数；仅商品ID、SKU编号、内部型号ID或标价不同，不据此增加款式数。当前目录可验证属性为名称、颜色、尺寸、重量及单位、中英文描述和商品子类；空值与空字符串统一，大小写、全半角和连续空白的书写差异不算商品差异。该口径不再按product_model_id合并不同颜色或尺寸。

程序只统计最终用户可见回答中的商品卡片，不把检索候选、工具结果、编号提及或“找到三款”这种声明当作实际展示。按当前两种服务器卡片格式解析商品编号，再从独立SQL取回真实属性核对。未来新增输出格式时，应同步更新卡片解析测试，不能默默跳过数量验收。

独立SQL读取完整头盔子类（31）的记录，按任务卡最终预算及其他明确条件计算可用不同款数。该范围不受工具候选截断影响。实际应展示数为min(用户要求数,完整范围内不同款数)，每款都必须符合条件且不得重复；实际数量不足时必须明确说明不足或没有符合条件的商品。没有查询到候选不能替代完整范围的不足证明。

原有预算、权限、数据写入、工具轨迹及模型回答评分继续生效。新增确定性检查失败时，即使模型裁判说通过也不通过。数量检查以最终交付为对象，不能据此声称首次回答已经正确；首次完成率仍需另行统计。

v2的100段对话及91/100原始成绩保持不变。v3另开运行目录、保存版本与哈希；不能将新规则下的分数直接当作业务能力提升，也不能沿用v2报告目录续跑。本次只更新评测，客服推荐的型号去重等业务逻辑没有修改。

## 执行方式

每个任务卡规定初始请求、用户目标、可知信息和验收条件。第一条输入固定，后续消息由模型根据客服实际回复生成，最多四轮。要求修改条件的场景至少两轮。模拟用户不能看到SQL参考事实、工具内部数据或任务状态，也不能生成裁判分数。

模拟用户宣布结束仅停止交互。另一次调用检查模拟用户是否偏题，偏题记为测试器无效，不记为客服业务失败。该检查也有模型偏差，原始对话必须保留供人工复核。

每个会话使用CurrentFixture创建隔离业务schema和独立thread，清理时只删除这次创建的对象。目录只读。执行工具通过原观察器记录，禁止业务写入；数据库快照、订单归属、金额、实际任务条件和AgentEvals轨迹检查独立于模型评分。最终用SQL事实与整段对话评估任务完成情况。

## 运行

```bash
python -m unittest tests.test_dynamic_evaluation -v
python -m evals.dynamic_runner

# 先冒烟，随后固定20场景，每场景五次；消耗模型额度
LANGSMITH_TRACING=false python -m evals.dynamic_runner --live --ids D02,D11
LANGSMITH_TRACING=false python -m evals.dynamic_runner --live --repeat 5
```

关闭追踪只影响当前评测进程，可避免云端追踪限额阻塞日志上传；本地事件与完整工具记录仍保留。不会修改项目.env或线上服务配置。

每个会话完成即保存。`--resume 报告目录`在场景、重复次数、代码和源数据指纹一致时跳过已有结果，不重放已完成的会话；中断时的in_progress记录单独保留，不能当作完整成绩。

## 报告

- report.json记录原始对话、工具与模型调用、SQL参考、用户模拟器决策和有效性检查、评分与代码/数据哈希。
- summary.md区分计划数量、完成数量、有效评分数量、单次通过率及全部重复通过的场景比例。
- 对话原文.md只展示输入与回答，便于独立人工复核。
- events.jsonl记录本次图执行事件。云端追踪关闭时不得声称LangSmith已经收到链路。

所有运行输出默认位于evals/reports_dynamic并被Git忽略。自动测试和真实模型成绩分别报告。模拟用户、客服和裁判使用同一模型服务，存在同源偏差；未做人工复核前只能称自动评分。无效模拟、评审不可用及未完成批次不能混入业务成功率。五次重复的可靠性结果是本样本上五次全部通过的场景比例，不是挑选五次中的最佳结果。
